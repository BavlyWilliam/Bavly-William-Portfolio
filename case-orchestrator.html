Prototype

AI model orchestrator

Personal project

Takes a request, asks follow-up questions when something important is missing, and recommends an AI model with its reasons, using live benchmark data.

Built with: Python, Gemini API, Pydantic, SQLite

  • Read the code

The problem

Picking an AI model for a task usually means guessing, or using one model for everything regardless of cost, speed or quality.

Constraints

  • Recommendations must come with reasons, not just a name.
  • Benchmarks change, so the data has to be live.
  • Every decision should be traceable afterwards.

How it works

  1. User request
  2. Clarify missing information
  3. Analyse requirements
  4. Score and optionally improve the prompt
  5. Score models with benchmark data and constraints
  6. Recommend with reasons
  7. Log to SQLite

Decisions and why

Structured outputs with Pydantic

Gemini's answers are parsed into typed objects and rejected if they don't fit, instead of scraping free text.

Ask before guessing

If something that changes the answer is missing, the tool asks a clarifying question first.

SQLite with foreign keys and parameterised queries

Requests, analyses and recommendations are linked and queryable, and parameters keep user text out of the SQL itself.

Results

  • Working command-line prototype with live benchmark data and a full history of runs.

Limits

  • Recommendations depend on what the benchmark data covers.
