WhatsApp purchase logger

Freelance client, small business

Selenium drives WhatsApp Web directly in Firefox, classifies every message in the client's purchase group and writes each purchase to Google Sheets, where an analysis tab shows the top spender against budget, the top vendor and the top-spending project.

Built with: Python, Selenium, Google Sheets API, OAuth, Gemini API

The problem

Staff at a small business report purchases in a dedicated WhatsApp group. The owner needed every purchase in a spreadsheet, by person, to compare spending against budget.

Constraints

  • Free or close to free to run.
  • Staff keep using WhatsApp. No new app, no new habit.
  • Messages are typed by people: typos, missing fields, Arabic and English.
  • Runs on a Windows PC.

How it works

  1. WhatsApp group
  2. Selenium driving WhatsApp Web in Firefox
  3. Classify the message
  4. Template parser
  5. Validator
  6. AI fallback (Gemini), then the validator again
  7. Google Sheet
  8. Analysis in the sheet: top spender against budget, top vendor, top-spending project

Decisions and why

Drive WhatsApp Web directly with Selenium in Firefox

No paid WhatsApp API and no third-party service: it reads the group the client already uses. Firefox proved more reliable than Chrome for this in an earlier WhatsApp project.

Rules first, AI second

A regex parser reads well-formed messages for free and the same way every time. Only messages it can't read go to Gemini, which keeps cost and surprises down.

Never trust the model's answer

Whatever Gemini returns passes the same validator as a typed template, so a model mistake can't write a bad row. AI rows are marked 'ai' in the sheet for spot checks.

Take buyer and date from WhatsApp, not from the message

The sender's contact name is the buyer and the message timestamp is the date, so staff type less and can't get those two wrong.

No keyword required

The group exists only for purchases, so any message with item, quantity and amount counts. One less thing for staff to remember.

One config block per client

Each client has its own group, sheet, token and log in clients.json, so a new client is configuration, not new code.

What broke, and the fix

Problem: Restarting the script skipped messages sent while it was off.

Fix: At start-up it rebuilds the list of logged messages from the sheet itself, so a restart skips what is already there and picks up what is new.

Problem: After a restart, the duplicate check read the wrong sheet column, so messages already logged could be written again.

Fix: Writing and reading now share one column layout, and a pytest test writes a row and checks that a restart recognises it.

Problem: Google access expired every 7 days.

Fix: Published the OAuth app, which removes the 7-day token expiry that applies to apps in testing.

Problem: The listener silently read the wrong chat.

Fix: It now checks the chat header after opening the group and on every polling cycle, and stops loudly on a mismatch instead of logging someone else's messages.

Results

  • Runs end to end: message in, validated row in the client's sheet.
  • The logged data answers the owner's real questions: who spends most against their budget, which vendor gets the most money, and which project costs the most.
  • Handles typos in field names through the AI fallback, with every AI row validated and labelled.
  • A pytest suite covers the parser, the validator, the AI fallback's handling and restart de-duplication, with no network calls.

Limits

  • WhatsApp's terms restrict unofficial automation, so this suits a business's own groups, not mass use.
  • It reads only messages loaded on screen.
  • Identical messages from one sender in the same minute count as one.
  • It runs while the PC is on. There is no server yet.

Next

  • Move message history to SQLite, with a retry queue for failed sheet writes.
  • Run it as a Windows background task so it survives restarts.
